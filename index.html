Section 01
What is the Transport Layer?
The transport layer provides logical communication between application processes running on different hosts — building on top of the network layer's host-to-host delivery.

🏠 The Household Analogy

Imagine Ann's house and Bill's house, each with 12 kids sending letters to each other.

🏠Houses = Hosts (computers)
👦Kids = Processes (apps)
✉️Letters = App messages
👩‍👧Ann & Bill sorting mail = Transport protocol
📮Postal service = Network layer (IP)
Key Distinction
NETWORK LAYER
Logical comm between hosts
TRANSPORT LAYER

Section 03
UDP — User Datagram Protocol
The "no frills" transport protocol. Fast, lightweight, and brutally simple. No handshakes, no guarantees — just send and hope.
⚡
Advantage
No Connection Setup
No handshake RTT delay. Just send! Perfect when latency matters more than reliability (DNS queries, gaming).
🪶
Advantage
Tiny Header
Only 8 bytes: source port, dest port, length, checksum. Compare to TCP's 20+ bytes. Less overhead = more data.
🌊
Advantage
No Congestion Control
Can blast data as fast as desired! Great for live streaming where a dropped frame is better than a delayed one.

🔍 UDP Segment Structure — Click any field to learn more

Source Port #
16 bits
Port of the sending application
The source port identifies which application process on the sender is sending this datagram. The receiver uses this to know where to reply. Optional in UDP — can be set to 0 if no reply needed.
Dest Port #
16 bits
Port of the target application
The destination port is the KEY for demultiplexing. The receiver checks this value to know which socket/process should receive this segment. E.g., port 53 = DNS, port 161 = SNMP.
Length
16 bits
Length of header + data in bytes
Total length of the UDP segment (header + payload) in bytes. Minimum value is 8 (header only, no data). Maximum is 65,535 bytes, but practically limited by IP's max datagram size.
Checksum
16 bits
Error detection (one's complement sum)
The checksum detects bit errors (flipped bits) during transmission. Computed as the one's complement sum of all 16-bit words in the segment. If receiver's computed checksum ≠ received checksum → error detected. But note: equal checksums doesn't guarantee no errors (weak protection)!
Application Data
variable
The payload — actual message content
The actual data from the application layer. For DNS, this would be a query or response. For a game, it might be a player's position update. UDP delivers this as-is with no modification.

Real World
Where UDP is Used
🌐
DNS
Domain lookups. Short queries, short responses. Speed matters. If it fails, just retry — no need for TCP overhead.
📺
Streaming Video
Loss tolerant — a missed frame is okay. Rate sensitive — can't afford TCP's retransmission delays for live video.
🎮
Gaming / VoIP
Old data is useless. A stale player position update is worse than no update. Latency beats reliability.
📡
SNMP
Network management. Should work even when network is congested. Lightweight polling.
🚀
HTTP/3 (QUIC)
Runs over UDP but adds its own reliability + congestion control at the application layer!
🔧
Custom Apps
Developers can build custom reliability on top of UDP when they need fine-grained control.
Section 04
TCP — Transmission Control Protocol
The reliable workhorse of the internet. Full-duplex, connection-oriented, with flow control, congestion control, and guaranteed ordered delivery.
🔒
Core Feature
Point-to-Point
One sender, one receiver. Not broadcast/multicast. A dedicated virtual circuit between exactly two endpoints.
↔️
Core Feature
Full Duplex
Data flows in BOTH directions simultaneously on the same connection. Both sides can be sender and receiver at once.
📬
Core Feature
Cumulative ACKs
ACK #100 means "I got everything up to byte 99, send me byte 100 next." One ACK covers many segments.

🔍 TCP Segment Structure — Click any field

Source Port
16 bits
Sending application's port
Identifies the sending process. Part of the 4-tuple that uniquely identifies a TCP connection (src IP, src port, dest IP, dest port). Used by the receiver to send replies back.
Dest Port
16 bits
Target application's port
The destination port number used with dest IP for demultiplexing. Well-known ports: 80 (HTTP), 443 (HTTPS), 22 (SSH), 21 (FTP). Client ports are usually ephemeral (1024–65535).
Sequence Number
32 bits
Byte-stream position of first byte
TCP numbers every BYTE in the stream, not every segment. The sequence number is the byte index of the first byte of data in this segment. Starts at a random ISN (Initial Sequence Number) chosen during the handshake. Enables ordering and detection of duplicates.
Acknowledgement #
32 bits
Next byte expected from other side
If ACK bit is set, this field says: "I've received all bytes up to ACK-1, I'm expecting byte ACK next." It's CUMULATIVE — one ACK covers everything up to that point. Example: ACK=100 means bytes 0–99 received, send 100 next.
Control Flags
6 bits
SYN, ACK, FIN, RST, PSH, URG
Each flag is 1 bit: SYN: synchronize seq numbers (connection setup) | ACK: acknowledgement field is valid | FIN: sender is done sending (connection teardown) | RST: reset / abort connection | PSH: push data to app immediately | URG: urgent data present
Receive Window (rwnd)
16 bits
Flow control: bytes receiver can accept
The key to TCP flow control! The receiver advertises how much free buffer space it has. The sender must not send more than rwnd bytes of unacknowledged data at any time. When rwnd=0, sender stops. Default buffer is typically 4096 bytes but modern OSes auto-adjust.
Checksum
16 bits
Error detection
Same one's complement checksum as UDP but covers the entire TCP header and data. In TCP it is MANDATORY (not optional). Also covers a pseudo-header including the source and destination IP addresses.

⏱️ RTT Estimation & Timeout Calculation

TCP dynamically estimates the Round-Trip Time to set a smart timeout. Drag the slider to see how EWMA smooths out variable SampleRTT values.

EstimatedRTT = (1-α) × EstimatedRTT + α × SampleRTT
DevRTT = (1-β) × DevRTT + β × |SampleRTT - EstimatedRTT|
TimeoutInterval = EstimatedRTT + 4 × DevRTT
α = 0.125 (weight for new sample)
β = 0.25 (weight for deviation)
The 4×DevRTT adds a safety margin

Too short timeout → premature retransmit (wasted bandwidth) | Too long timeout → slow to react to actual loss. The formula balances both!

❌ Why NOT 2-Way Handshake?

A 2-way handshake has two dangerous failure modes due to variable network delays and retransmissions.

Problem 1: Half-Open Connection
Client sends req_conn(x), server responds with acc_conn(x). But client retransmitted a delayed copy of req_conn(x) earlier. Server receives it after the original connection closed → server opens a connection with no client!
Problem 2: Duplicate Data Accepted
A retransmitted old data packet arrives at the server long after the original connection ended. Without the 3rd handshake message, server accepts it as new data from a "new" connection → corrupt data!
The 3rd message (ACK from client) gives the server confirmation that the client is ALIVE and knows the correct sequence numbers. This prevents stale connection re-establishment.

Section 07
TCP Congestion Control
When the network gets overloaded, TCP automatically slows down. This prevents collapse and is fair to all users sharing the network.
Flow Control = don't overwhelm the receiver's buffer
Congestion Control = don't overwhelm the network
Both are needed! TCP limits sending to min(cwnd, rwnd) bytes.

🐢 → 🐇 Slow Start

Despite the name, Slow Start grows exponentially fast!

  • Initial cwnd = 1 MSS (max segment size)
  • Each ACK received → cwnd += 1 MSS
  • Every RTT → cwnd doubles!
  • Stops when cwnd reaches ssthresh
  • On timeout: ssthresh = cwnd/2, restart from 1
RTT progression:
RTT 0: cwnd = 1 MSS
RTT 1: cwnd = 2 MSS
RTT 2: cwnd = 4 MSS
RTT 3: cwnd = 8 MSS
RTT 4: cwnd = 16 MSS
↑ Until ssthresh reached

📈 Congestion Avoidance

Once cwnd ≥ ssthresh, switch to linear growth — probe carefully for available bandwidth.

  • cwnd += 1 MSS per RTT (additive)
  • Increase by 1/cwnd per ACK
  • Much slower — one MSS per round trip
  • On triple duplicate ACK: ssthresh = cwnd/2, cwnd = ssthresh (fast recovery)
  • On timeout: ssthresh = cwnd/2, cwnd = 1 (restart slow start)
The Logic

We're close to the network's capacity — detected a loss last time we were around here. So grow slowly, like feeling your way in the dark!

⚡ Fast Recovery

When 3 duplicate ACKs are received (a less severe loss signal than timeout), TCP recovers faster.

// On 3 duplicate ACKs:
ssthresh = cwnd / 2
cwnd = ssthresh + 3 // (3 for the 3 dup ACKs)
// Retransmit missing segment
// For each additional dup ACK:
cwnd += 1
// When new ACK arrives:
cwnd = ssthresh // deflate
Enter Congestion Avoidance

📐 AIMD — Additive Increase, Multiplicative Decrease

The big picture of TCP's congestion behavior: gently probe up, cut hard on congestion.

ADDITIVE INCREASE
+1 MSS per RTT until loss detected. Probing gently.
MULTIPLICATIVE DECREASE
Cut cwnd in HALF on loss. Backs off hard.
